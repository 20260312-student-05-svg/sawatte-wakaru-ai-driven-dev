# 1. システム概要

- システム名：オンライン予約管理システム（クリニック向け）
- システムの目的：患者がオンラインで「予約・確認・キャンセル」でき、管理者が予約状況を一覧で把握できるようにして、電話/紙台帳運用の負担・ミス（二重予約、連絡漏れ）を減らす
- 想定ユーザー：
  - 患者
  - 受付担当者（管理者）

## 3-2. 各仕様の詳細

### 機能名または画面名：予約枠選択（新規予約）

- 利用者：患者
- 目的：受付時間外でも、空き時間を確認して予約できるようにする
- 事前条件：
  - 管理者が予約枠設定（診療時間・休診日・枠単位・1枠あたりの人数）を登録済み
- 入力項目：
  - 日付（必須）
  - 時間枠（必須）
  - （任意）診療科/メニュー（※シナリオ上は「クリニック」単一想定。必要なら要確認）
- 表示項目：
  - 選択した日付の時間枠一覧
  - 空き/満枠の状態
- 操作：
  - 日付を選ぶ → 空き枠を選ぶ → 「予約に進む」
- 正常時の結果：
  - 選択した枠を保持して「利用者情報入力」へ遷移する
- 備考：
  - 予約単位・休診日・診療時間・1枠あたりの人数は管理者の初期設定で決定する

### 機能名または画面名：利用者情報入力（初回：氏名＋電話／2回目以降：個人番号）

- 利用者：患者
- 目的：予約を「本人の予約」に紐づけられるように、利用者を特定する
- 事前条件：
  - 予約枠選択済み
- 入力項目：
  - 個人番号（2回目以降：必須）
  - 氏名（初回：必須）
  - 電話番号（初回：必須）
- 表示項目：
  - 選択した予約日時
  - 入力フォーム（個人番号 または 氏名＋電話番号）
- 操作：
  - 「2回目以降の方：個人番号で進む」→ 個人番号入力 → 「次へ」
  - 「初めての方：氏名＋電話で進む」→ 氏名/電話入力 → 「次へ」
- 正常時の結果：
  - 個人番号が有効なら、利用者が特定され「予約入力」へ
  - 初回の場合、氏名＋電話番号の紐づけ（ユーザー登録/認証完了）を行い「予約入力」へ
- 備考：
  - 個人番号は初回予約完了時に付与される（最小構成では“次へ進むための本人特定”として扱う）

### 機能名または画面名：予約入力（新規予約）

- 利用者：患者
- 目的：患者情報を登録して予約を確定する
- 事前条件：
  - 予約枠選択済み
  - 利用者が特定済み（初回：氏名＋電話番号の紐づけ完了／2回目以降：個人番号で特定済み）
- 入力項目：
  - （初回のみ）氏名（必須）
  - （初回のみ）電話番号（必須）
  - （任意）備考/コメント（最小構成では無しでも可）
- 表示項目：
  - 選択した予約日時
  - 入力フォーム（初回は氏名、電話番号／2回目以降は省略または確認表示のみ）
- 操作：
  - 必須項目入力 → 「予約する」
- 正常時の結果：
  - 二重予約チェックを行い、空きがあれば予約登録され「予約完了」へ
- 備考：
  - 初回で紐づけが完了したら、予約完了画面で「個人番号」を発行・表示する

### 機能名または画面名：予約完了

- 利用者：患者
- 目的：予約が成功したことを分かりやすく伝える
- 事前条件：
  - 予約登録が成功している
- 入力項目：なし
- 表示項目：
  - 予約番号（発行するなら）
  - 予約日時、氏名、電話番号（マスク可）
  - （初回のみ）個人番号（予約完了時に付与。次回以降の予約/確認/キャンセルで利用）
- 操作：
  - 「予約確認へ」などの導線
- 正常時の結果：
  - 予約情報が確認できる

### 機能名または画面名：予約確認（患者）

- 利用者：患者
- 目的：電話せずに自分の予約を確認できるようにする
- 事前条件：
  - 予約済み
- 入力項目：
  - 個人番号（必須）
  - （初回移行期の救済として）氏名＋電話番号（要確認：残すかどうか）
- 表示項目：
  - 「今後の予約」一覧（日時、状態）
- 操作：
  - 個人番号を入力 → 「検索」
- 正常時の結果：
  - 条件に一致する予約（今後分）が表示される
- 備考：
  - 「同姓同名」や電話番号変更時の扱い（未確定）

### 機能名または画面名：予約キャンセル（患者）

- 利用者：患者
- 目的：キャンセル連絡漏れを減らし、枠を空けられるようにする
- 事前条件：
  - 患者の予約が特定できている（予約確認から遷移する想定）
- 入力項目：
  - キャンセル対象（予約ID等）
  - （任意）キャンセル理由
- 表示項目：
  - キャンセル確認ダイアログ（日時、注意事項）
- 操作：
  - 「キャンセルする」→ 確認 → 実行
- 正常時の結果：
  - 予約状態が「キャンセル」に更新され、枠が空きになる
- 備考：
  - 当日キャンセル可否・締切（未確定事項として残す）

### 機能名または画面名：予約一覧（管理者）

- 利用者：受付担当者（管理者）
- 目的：台帳確認の手作業を減らし、二重予約や漏れを減らす
- 事前条件：
  - 管理者として利用できる（ログイン等は未確定でも可。最小では「管理者画面は別URL」など前提でもよい）
- 入力項目：
  - 日付（必須）
  - 期間（任意：開始日/終了日）
- 表示項目：
  - 予約一覧（日時、患者名、電話、状態）
  - 枠ごとの空き/満枠（出せるなら）
- 操作：
  - 日付/期間指定 → 一覧表示
- 正常時の結果：
  - 指定条件の予約が一覧表示される
- 備考：
  - 管理者の権限管理・認証方式（未確定）

### 機能名または画面名：予約枠設定（管理者）

- 利用者：受付担当者（管理者）
- 目的：診療時間・休診日・枠単位・1枠あたりの人数を初期設定し、予約の土台となる枠ルールを定める
- 事前条件：
  - 管理者として利用できる
- 入力項目：
  - 診療時間（開始時刻・終了時刻）
  - 休診日（曜日または日付指定）
  - 枠単位（例：30分単位）
  - 1枠あたりの人数（定員）
- 表示項目：
  - 現在の設定値
- 操作：
  - 各項目を設定 → 保存
- 正常時の結果：
  - 設定が保存され、予約枠のルールとして適用される

### 機能名または画面名：個人番号再発行（患者）

- 利用者：患者
- 目的：個人番号を忘れた場合に、氏名と電話番号で再発行を受ける
- 事前条件：
  - 氏名＋電話番号で登録済みの患者であること
- 入力項目：
  - 氏名（必須）
  - 電話番号（必須）
- 表示項目：
  - 本人確認後、個人番号を表示
- 操作：
  - 氏名・電話番号を入力 → 照合 → 個人番号を表示
- 正常時の結果：
  - 登録済みの氏名＋電話番号と一致した場合、個人番号が表示される

# 4. 業務ルール


| ルールID | 業務ルール                                                  | 対象機能               | 補足               |
| ----- | ------------------------------------------------------ | ------------------ | ---------------- |
| BR-01 | 予約は予約枠（日時）単位で管理する。枠の粒度・1枠あたりの人数は管理者の初期設定で決まる           | 新規予約/一覧/予約枠設定      | -                |
| BR-02 | 同一時間枠の予約数が管理者設定の定員に達したら新規予約できない                        | 新規予約               | 患者・管理者双方に適用      |
| BR-03 | 初回は「氏名＋電話番号」を紐づけ、2回目以降は「個人番号」で利用者を特定する。個人番号は初回予約完了時に付与 | 予約/確認/キャンセル        | -                |
| BR-04 | 予約確認・キャンセルは「個人番号」で行う。個人番号を忘れた場合は氏名＋電話番号で再発行可能          | 予約確認/キャンセル/個人番号再発行 | -                |
| BR-05 | キャンセルすると予約状態を「キャンセル」にし、枠を空きに戻す                         | キャンセル              | 当日キャンセルの締切は要確認   |
| BR-06 | 過去日時の新規予約は不可                                           | 新規予約               | 「当日直前」をどう扱うかは要確認 |


# 5. エラー仕様


| エラーID | 発生条件                       | 利用者へのメッセージ例                  | 対応方法                             |
| ----- | -------------------------- | ---------------------------- | -------------------------------- |
| ER-01 | 必須項目が未入力（個人番号、または氏名/電話/日時） | 必須項目を入力してください                | 未入力項目を強調表示                       |
| ER-02 | 電話番号形式が不正                  | 電話番号の形式が正しくありません             | 例示（ハイフン可否など）を表示し再入力              |
| ER-03 | 過去の日時を予約しようとした             | 過去の日時は予約できません                | 選択に戻す                            |
| ER-04 | 予約枠が満枠/二重予約になる             | その時間はすでに埋まっています。別の時間を選んでください | 再選択へ誘導                           |
| ER-05 | 個人番号が存在しない/無効              | 個人番号が確認できませんでした              | 入力見直し、「個人番号を忘れた方」から氏名＋電話番号で再発行案内 |
| ER-06 | 予約確認で一致する予約がない             | 予約が見つかりませんでした                | 入力見直しを案内                         |
| ER-07 | キャンセル対象が存在しない/既にキャンセル済み    | すでにキャンセル済み、または対象の予約が見つかりません  | 一覧に戻す/再検索                        |


# 6. 未確定事項（チームで決定済み）

※以下は 2025/03/12 時点で決定し、本仕様に反映済み：

- 診療時間・休診日・枠単位・1枠あたりの人数 → 管理者側で初期設定可能
- 1枠の定員を超える予約は不可（患者・管理者とも）
- 個人番号は予約完了時に患者に付与
- 個人番号を忘れた場合は、氏名＋電話番号で再発行可能

# 7. 学び・気づき

- AIに任せてよかった点：シナリオから必要機能（予約登録/確認/キャンセル/一覧）を漏れなく洗い出し、仕様の骨組みを短時間で作れた
- 人が決める必要があった点：予約枠の粒度や容量、本人確認、当日キャンセルなど「業務ルール」の前提は人が決めないと仕様が確定しない
- 設計に進む前に仕様化してよかった点：画面/入力/エラー/業務ルールの不足が見え、次の設計（画面遷移やデータ項目）に必要な論点が明確になった
