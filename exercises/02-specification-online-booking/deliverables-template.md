# 1. システム概要
- システム名：オンライン予約管理システム（クリニック向け）
- システムの目的：患者がオンラインで「予約・確認・キャンセル」でき、管理者が予約状況を一覧で把握できるようにして、電話/紙台帳運用の負担・ミス（二重予約、連絡漏れ）を減らす
- 想定ユーザー：
  - 患者
  - 受付担当者（管理者）

# 2. 機能一覧
| 機能名 | 利用者 | 機能の説明 | 優先度 |
|------|------|------|------|
| 新規予約 | 患者 | 空き枠を選び、患者情報を入力して予約登録する | 必須 |
| 新規ユーザー認証（氏名＋電話番号の紐づけ） | 患者 | 初回利用時に氏名と電話番号を登録（紐づけ）し、ユーザーとして特定できるようにする | 必須 |
| 個人番号による予約枠の確保 | 患者 | 2回目以降は個人番号だけで予約枠を確保できる | 必須 |
| 予約確認 | 患者 | 自分の予約内容（今後の予約）を確認する | 必須 |
| 予約キャンセル | 患者 | 自分の予約をキャンセルする | 必須 |
| 予約状況一覧閲覧 | 管理者 | 当日/期間の予約を一覧で確認する | 必須 |
| 二重予約防止 | 患者・管理者 | 同一時間枠への重複予約を防ぐ（満枠なら予約不可） | 必須 |
| 入力チェック/エラー表示 | 患者・管理者 | 未入力・不正値・満枠などを分かりやすく通知する | 必須 |
| 予約変更 | 患者 | 予約を変更する（最小構成では「キャンセル→再予約」で代替可） | あるとよい |
| 予約履歴参照 | 患者 | 過去の予約を確認する | 今回は対象外候補 |
| リマインド通知 | 患者 | 受診前に通知する | 今回は対象外候補 |
| 管理者による電話予約登録 | 管理者 | 電話で受けた予約もシステムに登録する | 要確認 |

# 3. 画面・機能仕様

## 3-1. 仕様一覧
| 機能名または画面名 | 利用者 | 目的 |
|------|------|------|
| 予約枠選択（新規予約） | 患者 | 空き枠を見つけて予約に進む |
| 利用者情報入力（初回：氏名＋電話／2回目以降：個人番号） | 患者 | 利用者を特定し、予約を本人に紐づける |
| 予約入力（新規予約） | 患者 | 必要情報を入力して予約登録する（初回は氏名＋電話の紐づけを行う） |

| 予約キャンセル（患者） | 患者 | 予約を取り消す |
| 予約一覧（管理者） | 管理者 | 予約状況を一覧で把握する |

## 3-2. 各仕様の詳細

### 機能名または画面名：予約枠選択（新規予約）
- 利用者：患者
- 目的：受付時間外でも、空き時間を確認して予約できるようにする
- 事前条件：
  - 予約枠（診療日/時間）が登録済み（登録方法は要確認）
- 入力項目：
  - 日付（必須）
  - 時間枠（必須）
  - （任意）診療科/メニュー（※シナリオ上は「クリニック」単一想定。必要なら要確認）
- 表示項目：
  - 選択した日付の時間枠一覧
  - 空き/満枠の状態
- 操作：
  - 日付を選ぶ → 空き枠を選ぶ → 「予約に進む」
- 正常時の結果：
  - 選択した枠を保持して「利用者情報入力」へ遷移する
- 備考・要確認事項：
  - 予約単位（例：30分単位）はチーム前提で決める（`inputs.md` の例に沿うなら30分）
  - 休診日や診療時間の扱い（未確定）

### 機能名または画面名：利用者情報入力（初回：氏名＋電話／2回目以降：個人番号）
- 利用者：患者
- 目的：予約を「本人の予約」に紐づけられるように、利用者を特定する
- 事前条件：
  - 予約枠選択済み
- 入力項目：
  - 個人番号（2回目以降：必須）
  - 氏名（初回：必須）
  - 電話番号（初回：必須）
- 表示項目：
  - 選択した予約日時
  - 入力フォーム（個人番号 または 氏名＋電話番号）
- 操作：
  - 「2回目以降の方：個人番号で進む」→ 個人番号入力 → 「次へ」
  - 「初めての方：氏名＋電話で進む」→ 氏名/電話入力 → 「次へ」
- 正常時の結果：
  - 個人番号が有効なら、利用者が特定され「予約入力」へ
  - 初回の場合、氏名＋電話番号の紐づけ（ユーザー登録/認証完了）を行い「予約入力」へ
- 備考・要確認事項：
  - 個人番号の発行タイミング（初回の予約完了時に付与する等）は要確認
  - 個人番号の入力だけで「予約枠の確保」まで行うか（仮確保の概念を入れるか）は要確認（最小構成では“次へ進むための本人特定”として扱う）

### 機能名または画面名：予約入力（新規予約）
- 利用者：患者
- 目的：患者情報を登録して予約を確定する
- 事前条件：
  - 予約枠選択済み
  - 利用者が特定済み（初回：氏名＋電話番号の紐づけ完了／2回目以降：個人番号で特定済み）
- 入力項目：
  - （初回のみ）氏名（必須）
  - （初回のみ）電話番号（必須）
  - （任意）備考/コメント（最小構成では無しでも可）
- 表示項目：
  - 選択した予約日時
  - 入力フォーム（初回は氏名、電話番号／2回目以降は省略または確認表示のみ）
- 操作：
  - 必須項目入力 → 「予約する」
- 正常時の結果：
  - 二重予約チェックを行い、空きがあれば予約登録され「予約完了」へ
- 備考・要確認事項：
  - 初回で紐づけが完了したら、次回以降利用できる「個人番号」を発行・表示する（表示内容の詳細は要確認）

### 機能名または画面名：予約完了
- 利用者：患者
- 目的：予約が成功したことを分かりやすく伝える
- 事前条件：
  - 予約登録が成功している
- 入力項目：なし
- 表示項目：
  - 予約番号（発行するなら）
  - 予約日時、氏名、電話番号（マスク可）
  - （初回のみ）個人番号（次回以降の予約/確認/キャンセルで利用）
- 操作：
  - 「予約確認へ」などの導線
- 正常時の結果：
  - 予約情報が確認できる

### 機能名または画面名：予約確認（患者）
- 利用者：患者
- 目的：電話せずに自分の予約を確認できるようにする
- 事前条件：
  - 予約済み
- 入力項目：
  - 個人番号（必須）
  - （初回移行期の救済として）氏名＋電話番号（要確認：残すかどうか）
- 表示項目：
  - 「今後の予約」一覧（日時、状態）
- 操作：
  - 個人番号を入力 → 「検索」
- 正常時の結果：
  - 条件に一致する予約（今後分）が表示される
- 備考・要確認事項：
  - 「同姓同名」や電話番号変更時の扱い（未確定）

### 機能名または画面名：予約キャンセル（患者）
- 利用者：患者
- 目的：キャンセル連絡漏れを減らし、枠を空けられるようにする
- 事前条件：
  - 患者の予約が特定できている（予約確認から遷移する想定）
- 入力項目：
  - キャンセル対象（予約ID等）
  - （任意）キャンセル理由
- 表示項目：
  - キャンセル確認ダイアログ（日時、注意事項）
- 操作：
  - 「キャンセルする」→ 確認 → 実行
- 正常時の結果：
  - 予約状態が「キャンセル」に更新され、枠が空きになる
- 備考・要確認事項：
  - 当日キャンセル可否・締切（未確定事項として残す）

### 機能名または画面名：予約一覧（管理者）
- 利用者：受付担当者（管理者）
- 目的：台帳確認の手作業を減らし、二重予約や漏れを減らす
- 事前条件：
  - 管理者として利用できる（ログイン等は未確定でも可。最小では「管理者画面は別URL」など前提でもよい）
- 入力項目：
  - 日付（必須）
  - 期間（任意：開始日/終了日）
- 表示項目：
  - 予約一覧（日時、患者名、電話、状態）
  - 枠ごとの空き/満枠（出せるなら）
- 操作：
  - 日付/期間指定 → 一覧表示
- 正常時の結果：
  - 指定条件の予約が一覧表示される
- 備考・要確認事項：
  - 管理者の権限管理・認証方式（未確定）

# 4. 業務ルール
| ルールID | 業務ルール | 対象機能 | 補足 |
|------|------|------|------|
| BR-01 | 予約は予約枠（日時）単位で管理する | 新規予約/一覧 | 枠の粒度（例：30分）はチーム前提で決める |
| BR-02 | 同一時間枠が満枠の場合は新規予約できない | 新規予約 | 「容量1」か「複数人枠」かは要確認（最小は容量1） |
| BR-03 | 初回は「氏名＋電話番号」を紐づけ、2回目以降は「個人番号」で利用者を特定する | 予約/確認/キャンセル | 個人番号の発行・再発行は要確認 |
| BR-04 | 予約確認・キャンセルは原則「個人番号」で行う | 予約確認/キャンセル | 初回移行期の例外（氏名＋電話を許可するか）は要確認 |
| BR-05 | キャンセルすると予約状態を「キャンセル」にし、枠を空きに戻す | キャンセル | 当日キャンセルの締切は要確認 |
| BR-06 | 過去日時の新規予約は不可 | 新規予約 | 「当日直前」をどう扱うかは要確認 |

# 5. エラー仕様
| エラーID | 発生条件 | 利用者へのメッセージ例 | 対応方法 |
|------|------|------|------|
| ER-01 | 必須項目が未入力（個人番号、または氏名/電話/日時） | 必須項目を入力してください | 未入力項目を強調表示 |
| ER-02 | 電話番号形式が不正 | 電話番号の形式が正しくありません | 例示（ハイフン可否など）を表示し再入力 |
| ER-03 | 過去の日時を予約しようとした | 過去の日時は予約できません | 選択に戻す |
| ER-04 | 予約枠が満枠/二重予約になる | その時間はすでに埋まっています。別の時間を選んでください | 再選択へ誘導 |
| ER-05 | 個人番号が存在しない/無効 | 個人番号が確認できませんでした | 入力見直し、再発行案内（要確認） |
| ER-06 | 予約確認で一致する予約がない | 予約が見つかりませんでした | 入力見直しを案内 |
| ER-07 | キャンセル対象が存在しない/既にキャンセル済み | すでにキャンセル済み、または対象の予約が見つかりません | 一覧に戻す/再検索 |

# 6. 未確定事項
- 予約枠のルール（診療時間、休診日、何分単位、1枠あたり何人まで）
- 二重予約の定義（容量1固定か/同一患者の重複禁止を入れるか）
- 個人番号の発行タイミング（初回の予約完了時に付与する等）と表示方法
- 個人番号を忘れた/紛失した場合の再発行・照会方法
- 初回移行期の扱い（予約確認/キャンセルを氏名＋電話でも許可するか）
- 氏名＋電話番号の紐づけ変更（改姓・電話番号変更）をどう扱うか
- 当日キャンセルの締切、ペナルティの有無（今回は対象外でもよい）
- 管理者の認証・権限（最小構成の扱い方）
- 電話予約を併用する場合、管理者による「電話予約登録」が必要か

# 7. 学び・気づき
- AIに任せてよかった点：シナリオから必要機能（予約登録/確認/キャンセル/一覧）を漏れなく洗い出し、仕様の骨組みを短時間で作れた
- 人が決める必要があった点：予約枠の粒度や容量、本人確認、当日キャンセルなど「業務ルール」の前提は人が決めないと仕様が確定しない
- 設計に進む前に仕様化してよかった点：画面/入力/エラー/業務ルールの不足が見え、次の設計（画面遷移やデータ項目）に必要な論点が明確になった
